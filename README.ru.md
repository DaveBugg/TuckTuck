# TuckTuck

*[English version](README.md)*

Селфхостед панель учёта того, за что и когда вы платите. Серверы, VPN, прокси,
домены и SaaS-подписки одним списком по ближайшей оплате, с напоминаниями в
Telegram до того, как деньги спишутся.

Рассчитана на одного человека или мини-команду. Никакого SaaS и чужих аккаунтов
— одна команда на своей машине.

---

## Быстрый старт

Одна команда на чистом сервере. Docker поставится, если его нет, секреты
сгенерируются, база смигрирует, HTTPS включится сам:

```bash
curl -fsSL https://raw.githubusercontent.com/DaveBugg/TuckTuck/main/setup.sh | TUCKTUCK_DOMAIN=panel.example.com sh
```

Это весь минимум — одна переменная. A-запись домена должна уже смотреть на
сервер: сертификат выпускается сразу, и имя должно резолвиться. Пароль
администратора скрипт напечатает один раз, в конце.

С капчей и прокси до Telegram:

```bash
curl -fsSL https://raw.githubusercontent.com/DaveBugg/TuckTuck/main/setup.sh -o setup.sh
TUCKTUCK_DOMAIN=panel.example.com \
TURNSTILE_SITE_KEY=0x4AAAAAAA... \
TURNSTILE_SECRET_KEY=0x4AAAAAAA... \
TELEGRAM_PROXY_URL=socks5://user:pass@host:1080 \
sh setup.sh
```

Повторный запуск обновляет стек и **сохраняет прежние секреты** — перевыпуск
ключа шифрования сделал бы нечитаемыми все сохранённые токены ботов и креды.

За своим nginx или Traefik — добавьте `TUCKTUCK_SKIP_PROXY=1` и проксируйте свой
веб-сервер на `127.0.0.1:3000`.

### Все переменные скрипта

| Переменная | По умолчанию | Что это |
|---|---|---|
| `TUCKTUCK_DOMAIN` | — | **Обязательная.** Домен панели, только имя хоста |
| `TUCKTUCK_DIR` | `/opt/tucktuck` | Куда ставить |
| `TUCKTUCK_PORT` | `3000` | Порт приложения на loopback |
| `TUCKTUCK_TAG` | `latest` | Тег образов; конкретный фиксирует сборку |
| `TUCKTUCK_SKIP_PROXY` | `0` | `1` — не поднимать Caddy, свой прокси уже есть |
| `TUCKTUCK_PREFIX` | `tucktuck` | Префикс имён контейнеров; менять нужно только ради второй панели на том же хосте |
| `TUCKTUCK_TLS` | `auto` | `auto` — Let's Encrypt, для сервера напрямую в интернете; `cert.pem,key.pem` — свой сертификат, для Cloudflare Full (strict) |
| `TUCKTUCK_SKIP_DOCKER` | `0` | `1` — не ставить Docker, поставите сами |
| `TURNSTILE_SITE_KEY` | пусто | Cloudflare Turnstile, публичная половина |
| `TURNSTILE_SECRET_KEY` | пусто | Turnstile, секретная половина. Обе пустые = капчи нет |
| `TELEGRAM_PROXY_URL` | пусто | `socks5://` или `http://`, если Telegram с сервера закрыт |
| `SEED_ADMIN_EMAIL` | `admin@tucktuck.local` | Логин первого администратора |
| `NOTIFY_INTERVAL_SEC` | `300` | Как часто воркер проверяет напоминания |

Секреты — пароль базы, `TUCKTUCK_JWT_SECRET`, `TUCKTUCK_ENCRYPTION_KEY`,
`TUCKTUCK_WORKER_TOKEN` — скрипт генерирует сам и кладёт в `<каталог>/.env` с
правами 600. Задавать их руками нужно только при переезде установки на другую
машину: ключ шифрования обязан совпадать с данными, иначе сохранённые секреты
перестанут расшифровываться.

## Что это

Одно место, которое отвечает на два вопроса о вашей инфраструктуре: **за что и
когда я плачу** и **живо ли оно ещё**.

Оплату легко пропустить. Домен истекает во вторник, VPS выключают в выходные,
подписка продлевается по цене, которую вы собирались пересмотреть ещё полгода
назад. У каждого провайдера своя панель и свои письма-напоминания, и друг о
друге они не знают. TuckTuck — тот самый список, которого ни один из них не даст.

Рассчитано на одного человека или мини-команду, на своей машине: никакого SaaS,
чужих аккаунтов и телеметрии, наружу панель ходит только в Telegram и за курсами
валют.

## Что умеет

### Оплаты

Всё оплачиваемое лежит в одной таблице — серверы, VPN, прокси, домены и
SaaS-подписки — по ближайшей оплате, так что вверху экрана всегда то, что платить
раньше всего. Фильтры «ближайшие 3 / 7 / 14 дней», по типу, провайдеру и тегу;
поиск по названию, IP, домену и ссылке.

Период оплаты — число плюс единица: раз в 30 дней, раз в 3 месяца, раз в год.
Дни и месяцы здесь не одно и то же: 30 дней — это всегда ровно 30, а календарный
месяц переносит 31 января на 28 февраля.

Нажали **отметить оплату** — платёж ушёл в историю, дата сдвинулась на период. У
провайдера можно хранить ссылку на его биллинг, и на дашборде она стоит прямо
рядом с оплатой.

### Деньги

Суммы хранятся по валютам и не смешиваются. Работают и фиат, и крипта; у крипты
рядом с монетой стоит сеть — одна и та же монета в другой сети это другой адрес
и другая комиссия.

На дашборде видно **текущий месяц**, **следующий** и **год целиком** — по
настоящему расписанию платежей, а не усреднением. Годовая подписка не отдаёт по
одной двенадцатой каждый месяц: она приходит один раз и целиком, в свой месяц.
Кнопка с графиком раскрывает год по месяцам, и всплески на нём — это ровно ваши
квартальные, полугодовые и годовые счета.

Суммы по валютам точные. Под ними — итог, пересчитанный в одну валюту, выбранную
в настройках, по курсам из четырёх бесплатных источников с кешем на час. Если
курса какой-то валюты нет, она попадает в список непересчитанных, а не молча
выпадает из суммы.

### Напоминания в Telegram

Напоминания шлют боты, которых вы заводите сами у @BotFather, — по умолчанию за
двое суток и за сутки, у каждого ресурса свои сроки.

Ботов может быть несколько, у каждого свой фильтр по типу ресурса и тегам:
боевые серверы в один чат, домены и подписки в другой. Под каждым сообщением три
кнопки — **оплачено**, **отменить**, **удалить из панели**, — так что в обычном
случае панель открывать не нужно вовсе. Удаление требует второго нажатия, а
повторное нажатие ничего не повторяет.

**Окно тишины** не даёт боту писать ночью: часы задаются в часовом поясе панели,
общие или свои у каждого бота. Напоминание, попавшее в тишину, не теряется — оно
уходит, когда окно открывается.

Если Telegram с вашего сервера недоступен (а на части хостингов это так),
пропишите прокси SOCKS5 или HTTP — общий или для одного бота. Панель сама
проверяет доступность и говорит, какой путь работает.

### Мониторинг

CPU, память, диск, load и аптайм с каждой машины, раз в минуту. Агент — обычный
POSIX-скрипт: ни Node, ни Python, ни Docker на сервере не нужны. Серверу самой
панели агент не нужен вовсе.

Ставится либо **одной командой**, либо **по SSH прямо из панели** — вставили
ключ и смотрите, как идёт лог. Что при этом сохраняется, а что нет, —
в разделе [как устроен агент](#как-устроен-агент) ниже.

В таблице ресурсов значок мониторинга покрашен по худшему показателю машины:
оранжевый, если что-то нагружено, красный, если критично или машина замолчала.
Беду видно, не наводя мышь на каждую строку.

История — за 1, 7, 14 и 30 дней, с распределением по часам суток: «в какие часы
машина занята» — вопрос про местное время, поэтому часовой пояс это настройка.
Старые точки сворачиваются сами: от года истории по одной машине остаётся пара
тысяч строк вместо полумиллиона.

### Доступ и безопасность

Учётные записи заводит администратор, регистрации нет. Роли — `ADMIN` и `USER`,
а группы решают, кто какой ресурс видит: ресурс без группы виден только админам.

Вход прикрыт лимитом попыток (и по учётке, и по адресу) и, если нужно, капчей
Cloudflare Turnstile, которая настраивается в самой панели. Двухфакторка — TOTP,
включает сам пользователь. Сессии видны в профиле и гасятся по одной. Токены
ботов, пароли прокси и секрет капчи лежат зашифрованными; от поисковиков панель
закрыта тремя независимыми слоями.

### Интерфейс

Русский и английский, у каждого пользователя свой; язык бота отдельно — в чате
читателей больше одного. Светлая и тёмная темы. Длинные списки — валюты, часовые
пояса, провайдеры — с поиском, а не прокруткой.

### Чего ещё нет

Хранилище кредов с журналом раскрытия (схема и шифрование готовы, экрана нет),
оповещения о падении сервера, выгрузка резервных копий по расписанию.

## Как устроен агент

Агент — POSIX-скрипт: читает `/proc` и `df` и раз в минуту отправляет снимок.
Требовать на чужом сервере Node, Python или Docker значило бы не поставить его
на половину машин.

Ставится двумя способами:

- **По SSH из панели.** Вставляете текст ключа или загружаете файл — установка
  идёт на сервере, а её лог печатается в окне в реальном времени. Ключ живёт в
  памяти на время установки и никуда не записывается: в карточке остаются
  только адрес, порт, пользователь и отпечаток хостового ключа. Отпечаток
  запоминается при первом подключении и сверяется дальше — как это делает сам
  `ssh`.
- **Одной командой** из того же окна, под root. Она идемпотентна: повторный
  запуск обновляет агент и не плодит дубли расписания.

Обновление уже установленного агента не требует переменных вовсе — адрес и
токен берутся из его же файла настроек:

```bash
curl -fsSL https://panel.example.com/install.sh | sh
```

Серверу самой панели ничего из этого не нужно: метрики читаются из хостовых
`/proc` и `/`, примонтированных в контейнер только на чтение.

Минутные точки живут сутки, дальше сворачиваются в часовые средние, через месяц
— в суточные. От года истории по одной машине остаётся пара тысяч строк вместо
полумиллиона.

## Раскатка на сервер

Серверу не нужно ничего, кроме Docker: ни Node, ни сборки — образы приезжают
готовыми из GHCR. [Быстрый старт](#быстрый-старт) выше делает всё сам; после
него остаётся каталог с `docker-compose.yml`, `.env` и `deploy.sh`.

Обновление — одна команда, откуда угодно на сервере и без единой переменной:
домен и все секреты читаются из `.env` самой установки.

```bash
curl -fsSL https://raw.githubusercontent.com/DaveBugg/TuckTuck/main/setup.sh | sh
```

Она тянет свежие образы, накатывает миграции и перезапускает стек, а в отличие
от `deploy.sh` обновляет ещё и `docker-compose.yml` с конфигом Caddy — то есть
приносит новые сервисы и настройки.

Из каталога установки `./deploy.sh` делает то же самое для одного приложения, а
`./deploy.sh sha-a1b2c3d` откатывает на конкретную сборку.

Если ставить руками, из клона:

```bash
git clone https://github.com/DaveBugg/TuckTuck.git && cd TuckTuck
cp .env.example .env && nano .env    # домен, пароль БД, секреты
./scripts/deploy.sh
docker compose exec tucktuck node prisma/seed.mjs   # первый админ
```

`deploy.sh` тянет образы, прогоняет миграции отдельным контейнером, обновляет
приложение, ждёт `/api/health` и сверяет версию сборки в ответе. Если новая
версия не поднялась — печатает логи и откатывается на предыдущий тег.

> Откат возвращает образ, но **не откатывает миграции**. Ломающие изменения
> схемы стоит разбивать на совместимые шаги.

HTTPS поднимается сам: Caddy держит 80/443 и выпускает сертификат Let's Encrypt
для `TUCKTUCK_DOMAIN`. A-запись домена должна уже смотреть на сервер.

### HTTPS: два поддержанных режима

**1. Сервер смотрит в интернет напрямую, без Cloudflare.** Это режим по
умолчанию, никаких переменных не нужно:

```bash
curl -fsSL https://raw.githubusercontent.com/DaveBugg/TuckTuck/main/setup.sh | TUCKTUCK_DOMAIN=panel.example.com sh
```

Caddy держит 80/443, при первом запуске выпускает сертификат Let's Encrypt для
`TUCKTUCK_DOMAIN` и сам продлевает его заранее. Ни cron, ни certbot, ни второго
контейнера. Сертификаты лежат в именованном томе, поэтому пересоздание
контейнера не отправляет вас снова в Let's Encrypt — так и не упираются в их
лимиты.

Требований два, и оба про достижимость: A-запись домена уже смотрит на этот
сервер, а порты 80 и 443 открыты наружу. По ним приходит проверка ACME, и
закрытый 80-й — обычная причина, по которой выпуск не проходит.

**2. За Cloudflare, режим SSL/TLS Full (strict).** Посетители получают
сертификат Cloudflare; тот, что на вашем сервере, закрывает участок между
Cloudflare и вами, и в строгом режиме Cloudflare его проверяет. Выпустите у них
бесплатный Origin Certificate (SSL/TLS → Origin Server → Create Certificate),
положите оба файла на сервер и укажите на них:

```bash
curl -fsSL https://raw.githubusercontent.com/DaveBugg/TuckTuck/main/setup.sh -o setup.sh
TUCKTUCK_DOMAIN=panel.example.com TUCKTUCK_TLS=/root/origin.pem,/root/origin.key sh setup.sh
```

Файлы копируются в каталог установки, ключу выставляются права 600, а Caddy
перестаёт ходить в Let's Encrypt вовсе — и правильно, тот сертификат всё равно
никому не показывался бы. Origin Certificate живёт 15 лет; в этот день его
придётся заменить руками — той же командой с новыми файлами.

Повторный запуск `setup.sh` без `TUCKTUCK_TLS` сохраняет выбранный способ, так
что обновление не вернёт вас молча к Let's Encrypt.

> Режим **Flexible** не поддерживается намеренно. Cloudflare ходил бы к вашему
> серверу открытым HTTP, а панель редиректит всё на HTTPS — получается петля, и
> трафик между Cloudflare и вами шёл бы незашифрованным. Берите Full (strict).

<details>
<summary>Ещё два рабочих случая, которые нужны редко</summary>

`TUCKTUCK_TLS=internal` даёт Caddy самоподписанный сертификат — этого хватает
для режима **Full** (нестрогого), где Cloudflare сертификат сервера не
проверяет. Проще, чем Origin Certificate, и ничего не истекает.

Оставить `auto` за Cloudflare тоже можно, если порт 80 доходит до сервера:
Let's Encrypt просто выпустит настоящий сертификат для участка, которого никто
не видит.

</details>

**Свой nginx и certbot** — поднимайте без нашего прокси:

```bash
... TUCKTUCK_SKIP_PROXY=1 sh setup.sh
```

Приложение остаётся на `127.0.0.1:3000`, наружу не публикуется ничего.
Сертификаты и их продление — обычная работа certbot: его systemd-таймер живёт
своей жизнью, TuckTuck про него не знает и не мешает.

```nginx
server {
    listen 443 ssl;
    server_name panel.example.com;

    ssl_certificate     /etc/letsencrypt/live/panel.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/panel.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host  $host;

        # Установка агента печатает лог построчно. При буферизации по умолчанию
        # nginx придержит его и отдаст целиком в конце — со стороны это выглядит
        # ровно как зависшая установка.
        proxy_buffering off;
        proxy_read_timeout 600s;
    }
}
```

Заголовки здесь не для красоты. `X-Forwarded-For` попадает в список сессий, а по
`X-Forwarded-Proto` и `X-Forwarded-Host` панель понимает, какой адрес выдать
агенту мониторинга. Если задать в `.env` `TUCKTUCK_PUBLIC_URL`, он важнее обоих —
это имеет смысл, когда панель стоит за двумя прокси подряд.

### Воркер напоминаний

Воркер — отдельный контейнер из того же образа:

```bash
docker compose --profile workers up -d tucktuck-notify
```

Ходит в приложение по внутренней сети раз в `NOTIFY_INTERVAL_SEC` секунд. Будить
чаще раза в сутки безопасно: повторная отправка отсекается на уровне БД.

Чтобы работали кнопки под сообщениями, нужен `TUCKTUCK_PUBLIC_URL` — https-адрес,
до которого достучится Telegram. Без него напоминания всё равно приходят, просто
без кнопок; панель об этом предупреждает.

## CI

`.github/workflows/ci.yml` гоняет юниты на каждый пуш, а на `main` собирает и
публикует в GHCR два образа: приложение и мигратор. Теги — `latest`,
`sha-<короткий>` и семвер с git-тегов.

`NEXT_PUBLIC_*` впекаются в бандл на этапе сборки, поэтому задаются переменными
репозитория, а не серверным `.env`.

## Ориентиры в коде

| Путь | Что там |
|---|---|
| `src/lib/permissions.ts` | карта прав. Изоморфный модуль: edge-middleware, API и UI берут её отсюда |
| `src/lib/auth.ts` | подпись и проверка JWT, `requirePermission`, ревалидация в БД |
| `src/lib/resources.ts` | правило видимости, арифметика периодов, уровни срочности |
| `src/lib/notify.ts` | подбор напоминаний, фильтры ботов, текст сообщения |
| `src/lib/telegram.ts` | тонкий клиент Bot API |
| `src/lib/ssh-install.ts` | транспорт установки по SSH: отпечаток по TOFU, скрипт через stdin |
| `src/lib/monitoring.ts` | статус по свежести снимка, разбор того, что прислал агент |
| `src/lib/i18n/` | словари и движок подстановки (формы числа через Intl) |
| `public/agent.sh` | сам агент |
| `public/install.sh` | идемпотентный установщик, systemd-таймер или cron |
| `src/components/data-table.tsx` | серверные таблицы: поиск, сортировка, фильтры, действия строк |
| `src/components/ui/` | компоненты shadcn, принадлежат этому репозиторию |

Код проверяет **право**, а не роль. Роли лишь выдают наборы прав, поэтому новая
роль — одна строка в `ROLE_PERMISSIONS`.

Всё оплачиваемое — одна строка `Resource` с полем `kind`, а не пять моделей:
главный экран это единый список по всем типам, а пять таблиц означали бы UNION
из пяти запросов и пять копий оплат, напоминаний, кредов и тегов.

Язык интерфейса берётся сначала из куки и только потом из базы. Язык нужен
каждому экрану, и чтение из базы сделало бы его самым частым запросом системы.
Оттуда он читается один раз, при входе, и кладётся в куку.
