# TuckTuck

*[English version](README.md)*

Селфхостед панель учёта того, за что и когда вы платите. Серверы, VPN, прокси,
домены и SaaS-подписки одним списком по ближайшей оплате, с напоминаниями в
Telegram до того, как деньги спишутся.

Рассчитана на одного человека или мини-команду. Никакого SaaS и чужих аккаунтов
— один `docker compose up` на своей машине.

---

## Зачем

Оплаты за инфраструктуру легко пропустить: домен истекает во вторник, VPS
блокируют в выходные, подписка продлевается по цене, которую вы собирались
пересмотреть. У каждого провайдера своя панель и свои письма, и друг о друге они
не знают.

TuckTuck держит это в одной таблице: что, когда, сколько и у кого. За двое суток
и за сутки до оплаты бот пишет в Telegram. Отмечаете оплату прямо из чата — дата
сдвигается сама.

## Что умеет

| | |
|---|---|
| **Ресурсы** | Серверы, VPN, прокси, домены, SaaS — один список по ближайшей оплате |
| **Фильтры** | Ближайшие 3 / 7 / 14 дней, по типу, провайдеру и тегу; поиск по названию, IP, домену, ссылке |
| **Оплаты** | Отметка оплаты пишет платёж в историю и двигает дату на период |
| **Напоминания** | На каждый ресурс, в днях до оплаты; по умолчанию за 2 и за 1 |
| **Telegram** | Несколько ботов, у каждого свой фильтр по типу и тегам; кнопки под сообщением |
| **Мониторинг** | Свой агент — POSIX-скрипт, ни Node, ни Docker на машине не нужны. CPU, память, диск, load, аптайм; история за 1 / 7 / 14 / 30 дней и нагрузка по часам суток |
| **Установка агента** | Из панели по SSH с живым логом или одной командой. Приватный ключ нигде не сохраняется |
| **Деньги** | Фиат и крипта (монета + сеть), точные суммы по валютам и общий итог по курсу |
| **Авторизация** | JWT в HttpOnly-cookie, мультисессии с ревокацией, 2FA (TOTP), Cloudflare Turnstile |
| **Доступ** | Роли `ADMIN` и `USER`; группы решают, кто какой ресурс видит |
| **Языки** | Русский и английский, на каждого пользователя; язык бота настраивается отдельно |

### Чего ещё нет

Хранилище кредов с журналом раскрытия (схема и шифрование готовы, экрана нет),
выгрузка резервных копий по расписанию.

## Экраны

- `/dashboard` — что скоро оплачивать, расход за месяц, здоровье серверов
- `/resources` — главная таблица
- `/notifications` — Telegram-боты и их фильтры
- `/settings` — прокси, часовой пояс, срок хранения метрик, валюта итога, язык бота
- `/users` — учётки, роли, сброс паролей
- `/profile` — язык, пароль, двухфакторка, активные сессии

Регистрации нет: пользователей заводит администратор.

## Мониторинг

Агент — POSIX-скрипт: читает `/proc` и `df` и раз в минуту отправляет снимок.
Требовать на чужом сервере Node, Python или Docker значило бы не поставить его
на половину машин.

Ставится двумя способами:

- **По SSH из панели.** Вставляете текст ключа или загружаете файл — установка
  идёт на сервере, а её лог печатается в окне в реальном времени. Ключ живёт в
  памяти на время установки и никуда не записывается: в карточке остаются
  только адрес, порт, пользователь и отпечаток хостового ключа. Отпечаток
  запоминается при первом подключении и сверяется дальше — как это делает сам
  `ssh`.
- **Одной командой** из того же окна, под root. Она идемпотентна: повторный
  запуск обновляет агент и не плодит дубли расписания.

Серверу самой панели ничего из этого не нужно: метрики читаются из хостовых
`/proc` и `/`, примонтированных в контейнер только на чтение.

Минутные точки живут сутки, дальше сворачиваются в часовые средние, через месяц
— в суточные. От года истории по одной машине остаётся пара тысяч строк вместо
полумиллиона.

## Стек

Next.js 16 · TypeScript · Prisma · PostgreSQL 17 · Redis (кеш курсов) ·
Tailwind CSS v4 · shadcn/ui (Radix) · Caddy для автоматического HTTPS.

## Запуск локально

```bash
cp .env.example .env          # как минимум задать TUCKTUCK_JWT_SECRET
docker compose -f docker-compose.dev.yml up -d
npm install
npm run db:deploy
npm run db:seed               # напечатает пароль админа один раз
npm run dev                   # http://localhost:3000
```

## Раскатка на сервер

Серверу нужны только Docker, этот репозиторий и `.env`. Ни Node, ни сборки —
образы приезжают готовыми из GHCR.

```bash
git clone https://github.com/DaveBugg/TuckTuck.git && cd TuckTuck
cp .env.example .env && nano .env    # домен, пароль БД, секреты
./scripts/deploy.sh
docker compose exec tucktuck node prisma/seed.mjs   # первый админ
```

Обновление — `git pull && ./scripts/deploy.sh`. Откат на конкретную сборку —
`./scripts/deploy.sh sha-a1b2c3d`.

`deploy.sh` тянет образы, прогоняет миграции отдельным контейнером, обновляет
приложение, ждёт `/api/health` и сверяет версию сборки в ответе. Если новая
версия не поднялась — печатает логи и откатывается на предыдущий тег.

> Откат возвращает образ, но **не откатывает миграции**. Ломающие изменения
> схемы стоит разбивать на совместимые шаги.

HTTPS поднимается сам: Caddy держит 80/443 и выпускает сертификат Let's Encrypt
для `TUCKTUCK_DOMAIN`. A-запись домена должна уже смотреть на сервер.

### Напоминания

Воркер — отдельный контейнер из того же образа:

```bash
docker compose --profile workers up -d tucktuck-notify
```

Ходит в приложение по внутренней сети раз в `NOTIFY_INTERVAL_SEC` секунд. Будить
чаще раза в сутки безопасно: повторная отправка отсекается на уровне БД.

Чтобы работали кнопки под сообщениями, нужен `TUCKTUCK_PUBLIC_URL` — https-адрес,
до которого достучится Telegram. Без него напоминания всё равно приходят, просто
без кнопок; панель об этом предупреждает.

## CI

`.github/workflows/ci.yml` гоняет юниты на каждый пуш, а на `main` собирает и
публикует в GHCR два образа: приложение и мигратор. Теги — `latest`,
`sha-<короткий>` и семвер с git-тегов.

`NEXT_PUBLIC_*` впекаются в бандл на этапе сборки, поэтому задаются переменными
репозитория, а не серверным `.env`.

## Ориентиры в коде

| Путь | Что там |
|---|---|
| `src/lib/permissions.ts` | карта прав. Изоморфный модуль: edge-middleware, API и UI берут её отсюда |
| `src/lib/auth.ts` | подпись и проверка JWT, `requirePermission`, ревалидация в БД |
| `src/lib/resources.ts` | правило видимости, арифметика периодов, уровни срочности |
| `src/lib/notify.ts` | подбор напоминаний, фильтры ботов, текст сообщения |
| `src/lib/telegram.ts` | тонкий клиент Bot API |
| `src/lib/ssh-install.ts` | транспорт установки по SSH: отпечаток по TOFU, скрипт через stdin |
| `src/lib/monitoring.ts` | статус по свежести снимка, разбор того, что прислал агент |
| `src/lib/i18n/` | словари и движок подстановки (формы числа через Intl) |
| `public/agent.sh` | сам агент |
| `public/install.sh` | идемпотентный установщик, systemd-таймер или cron |
| `src/components/data-table.tsx` | серверные таблицы: поиск, сортировка, фильтры, действия строк |
| `src/components/ui/` | компоненты shadcn, принадлежат этому репозиторию |

Код проверяет **право**, а не роль. Роли лишь выдают наборы прав, поэтому новая
роль — одна строка в `ROLE_PERMISSIONS`.

Всё оплачиваемое — одна строка `Resource` с полем `kind`, а не пять моделей:
главный экран это единый список по всем типам, а пять таблиц означали бы UNION
из пяти запросов и пять копий оплат, напоминаний, кредов и тегов.

Язык интерфейса берётся сначала из куки и только потом из базы. Язык нужен
каждому экрану, и чтение из базы сделало бы его самым частым запросом системы.
Оттуда он читается один раз, при входе, и кладётся в куку.
