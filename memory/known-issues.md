# Известные грабли и неочевидные факты

## Инструментальные

- **Serena на Windows:** первый вызов в свежей сессии может поднимать LSP долго — не бросать в
  Read/Grep, дождаться. Если падает с «no active project» — проверить `.serena/project.yml`.
- **codebase-memory:** индексировать в режиме `fast` (`full` нестабилен); persistence пишет
  `.codebase-memory/graph.db.zst` (в `.gitignore` — каждый индексит сам). Ре-индекс не удаляет узлы
  исключённых файлов — для чистого пересбора `delete_project` → `index_repository`.
- Исключения графа — `.cbmignore` в корне (уже создан).
- **`next lint` удалён в Next 16**: скрипт `lint` теперь `eslint .`; `eslint-config-next` отдаёт
  flat config напрямую (FlatCompat с ним падает «circular structure»). Линт в репо долго не работал
  — при включении всплыло ~800 prettier-расхождений, прогнан `prettier --write` по репо.
- **react-hooks v6 (compiler-правила)**: `set-state-in-effect` и `static-components` выключены в
  `eslint.config.mjs` — кодовая база писалась до них, массовый рефакторинг не оправдан.
- Мёртвый `src/lib/react-apexcharts-safe.tsx` (импорт несуществующего `react-apexcharts-original`)
  ломал `type-check` на свежем клоне — удалён 2026-11-24, импортёров не было.
- **`npm audit` после Prisma 7.10.1 оставляет 3 high (effect <=3.22.0)** через транзитивную
  `@prisma/config`: уязвимость в библиотеке Effect, от которой зависит Prisma CLI/config.
  Ждём фикса со стороны Prisma; откат на 6.x не вариант (требуется driver adapter + v7 API).

## Проектные

- `deploy.sh` раньше игнорировал `TUCKTUCK_SKIP_PROXY` и безусловно поднимал `tucktuck-proxy` → на
  серверах со своим прокси деплой падал посередине на занятом 80-м порту (set -e обрывал до
  health-check и обновления воркера). Пофикшено 2026-11-25: прокси не тянется и не поднимается при
  SKIP_PROXY=1. При правках `setup.sh`/`deploy.sh`/`public/install.sh` прогонять `sh -n` и smoke.
- Healthcheck Docker-образа дёргает `/api/health` по HTTP — у воркера напоминаний порт не слушает,
  поэтому у `tucktuck-notify` healthcheck отключён сознательно (не «чинить»).
- Порт приложения публикуется на `127.0.0.1` — наружу только через Caddy. Это не ошибка
  конфигурации.
- Postgres-порт не опубликован наружу сознательно; внешний доступ — только ssh-туннель.
- Повторная отправка напоминаний блокируется на уровне БД — частые пробуждения воркера безопасны.
- Без `TUCKTUCK_PUBLIC_URL` кнопки под Telegram-напоминаниями не работают (вебхук не принимает
  localhost) — панель об этом предупреждает.
- Монтирование `/proc` и `/` хоста (ro) — чтобы метрики были сервера, а не контейнера (как
  node_exporter). Не убирать.
- Установка через `curl | sh` исторически падала синтаксической ошибкой на середине (фикс e283b7c) —
  при правках `setup.sh`/`public/install.sh` прогонять `sh -n` и smoke на чистой машине.
- **Смена `TUCKTUCK_ENCRYPTION_KEY` ломает хранимые секреты**: токены ботов, креды, прокси
  зашифрованы AES-256-GCM — старые записи не расшифровать.
- **Видимость ресурсов строго по группам**: ресурс без группы видит только ADMIN; USER — только
  ресурсы своих групп (`src/lib/resources.ts`).
- **Redis fail-open**: при недоступности rate-limit падает на in-memory, курсы/настройки — на
  БД/источники; вход не ломается. Не делать Redis обязательным.
- **Приватный SSH-ключ не сохраняется**: живёт в памяти на время установки; хостовый ключ — TOFU. Не
  добавлять его персистентность.
- **TG WebApp initData**: канонический алгоритм — `secret = HMAC(key="WebAppData", msg=botToken)`
  (не наоборот!) и `signature` ВКЛЮЧАЕТСЯ в check-string (исключается только `hash`). Проверено
  живым initData 2026-11-25. Грабля: тесты были самосогласованными (подписывали той же неверной
  схемой), поэтому баг жил с рождения — крипто-тесты сверять с реальными векторами, а не только
  self-sign. Отказы логируются с причиной (`[auth/telegram] rejected: <reason>`).
- **Встраиваемый браузер/куки**: cookies host-scoped (localhost ≠ 127.0.0.1, порт роли не играет);
  для параллельной проверки нескольких серверов использовать разные хосты.
- **Radix Popover внутри модального Dialog**: портал поповера пустеет/блокируется — компоненты
  поверх диалогов рендерить инлайн (как `date-picker.tsx`).
- **401 при живом JWT**: middleware доверяет подписи, сессия ревокнута в БД → клиент обязан звать
  `/api/auth/logout` до редиректа на логин (иначе цикл login↔dashboard). Реализовано в
  `client-api.ts`.
