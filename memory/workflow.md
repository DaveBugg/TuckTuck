# Workflow: правила работы и экономия токенов

## Порядок навигации по коду (заповедь)

1. **Код-граф** (`codebase-memory`, проект `C-Work-DebSrvk-TuckTuck`): `search_graph` / `trace_path`
   / `get_architecture` / `get_code_snippet` — ориентация и impact-анализ ~0 токенов.
2. **Serena** (LSP, TS): `get_symbols_overview` перед чтением файла; `find_symbol` (с `include_body`
   только когда нужно тело); `find_referencing_symbols` перед правкой публичных символов. Правки —
   `replace_symbol_body` / `insert_before/after_symbol` / `rename_symbol` (reference-aware).
3. **Grep/Glob** — когда 1–2 не покрыли (точные строки, конфиги, prisma-схема, shell).
4. **Read** — последнее средство; всегда с `line_offset`/`n_lines` для файлов >300 строк.

## Экономия токенов

- Не перечитывать файл после собственной правки — система подтверждает запись.
- Не читать целиком файлы ради одного символа — сначала overview/Serena.
- Разведка, массовые поиски, «составь карту/список» — сабагентам (`explore`); в основной контекст —
  только выводы.
- MCP-тулзы Kimi грузятся лениво: `select_tools` одной пачкой с нужными именами, не «про запас».
- Большие выхлопы команд — через фильтры (`head`, `grep`), не сырым stdout.
- Мозг читать точечно: один релевантный `memory/*.md` под задачу, не все.
- Прогресс-заметки между вызовами — одна строка, без пересказа каждого вызова.

## Стайлгайд кода проекта

- TypeScript строго; `npm run type-check` обязан быть чистым до коммита.
- Чистый код, DRY: не писать метод дважды — расширять существующий кейсами; повторяющаяся логика →
  класс/конструктор/фабрика.
- ООП там, где есть состояние/варианты поведения (сервисы, транспорты); простые чистые функции — для
  вычислений (как `resources.ts`).
- Именование и структура — по соседнему коду; комментарии только про «почему», не про «что» (стиль
  репо: поясняющие комментарии-блоки на русском там, где неочевидно — см. `docker-compose.yml`,
  `.gitignore`).
- shadcn/ui компоненты в `src/components/ui/` — собственность репо, можно править.
- Тесты — `tests/unit/*.test.ts` на tsx; новый файл добавить явно в скрипт `test:unit` в
  `package.json`.

## Проверки перед сдачей

`npm run type-check` → `npm run lint` → `npm test`. Если менялась схема — `db:migrate`. Прогнать
сценарий пользователя end-to-end, не только компиляцию. После прогонов — `git status`, убрать мусор,
который создали прогоны.

## Обновление памяти

- Нашёл неочевидное / изменил поведение → обнови нужный `memory/*.md` **в той же сессии**.
- Новая грабля → `memory/known-issues.md`.
- Новая подсистема/файлы → `memory/architecture-map.md`.
- Значимые изменения кода → ре-индекс графа: `index_repository` (mode `fast`, persistence `true`).
- Код противоречит доке — чини доку, не код.
