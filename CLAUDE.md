# TuckTuck — управляющий документ агентов

Self-hosted панель учёта платежей (серверы, VPN, домены, подписки) с напоминаниями в Telegram.
Next.js 16 · TypeScript · Prisma · PostgreSQL 17 · Redis · Tailwind v4 · shadcn/ui · Caddy.

Этот файл — общий для всех агентов (Claude Code, Kimi Code и др.). Держать компактным: он грузится
каждую сессию.

## ▶ Ритуал сессии

**Старт (до любого Grep/Read по коду):**

1. Serena: первый вызов — `get_symbols_overview` на любом код-файле (проверка, что LSP жив; если
   падает — проект не активирован).
2. Код-граф: `search_graph` / `get_architecture` по цели задачи (проект `C-Work-DebSrvk-TuckTuck`).
3. Мозг: таблица ниже → прочитать ОДИН релевантный файл, не все.

**Финиш (на вехах):** обновить нужный `memory/*.md` в той же сессии; после значимых изменений кода —
ре-индекс графа (`index_repository`, mode `fast`, persistence `true`). Код противоречит доке — чини
доку.

## Порядок навигации (дешевле → дороже)

1. **Код-граф** (`codebase-memory`): `search_graph`, `trace_path`, `get_architecture`,
   `get_code_snippet` — ориентация, «кто зовёт», impact (~0 токенов).
2. **Serena** (LSP): `get_symbols_overview` → `find_symbol` / `find_referencing_symbols` → правки
   `replace_symbol_body` / `insert_*` / `rename_symbol`.
3. **Grep/Glob** — если 1–2 не покрыли. **Read целого файла — последнее средство** (и то с
   `line_offset`/`n_lines`).

## Карта памяти (мозг проекта)

| Файл                         | Что внутри                                       |
| ---------------------------- | ------------------------------------------------ |
| `memory/overview.md`         | проект, стек, топология, команды                 |
| `memory/workflow.md`         | правила работы, экономия токенов, стайлгайд кода |
| `memory/architecture-map.md` | «где найти X»: фича → файл/символ                |
| `memory/environment.md`      | инфра, деплой, env-переменные (без секретов)     |
| `memory/known-issues.md`     | грабли, риски, неочевидные факты                 |
| `memory/dev-progress.md`     | текущий фокус и следующие шаги                   |

Роли: `memory/*.md` — источник правды; Serena memories — тонкие указатели на них; код-граф — карта
кода. Не дублировать факты между слоями.

## Правила кода

- Чистый код, ООП там, где это уместно по специфике проекта; **не дублировать методы** — расширять
  существующие кейсами, при необходимости выращивая в классы/конструкторы.
- Проверка **permission, не роли** (`src/lib/permissions.ts`, изоморфная карта: middleware/API/UI).
  Новая роль = одна строка в `ROLE_PERMISSIONS`.
- Всё оплачиваемое — одна строка `Resource` с `kind`, а не отдельные модели.
- Валидация/ошибки API — по устоявшемуся паттерну хендлеров (см. `memory/architecture-map.md`).
- Лучшие практики и паттерны, выявленные в работе, — записывать в `memory/workflow.md`.
- После изменений: `npm run type-check` (должен быть чист), `npm run lint`, `npm test`. Новые тесты
  — в `tests/unit/`, добавить в скрипт `test:unit`.

## Жёсткие запреты

- Секреты, ключи, дампы БД — не читать, не коммитить (см. `.gitignore`: `.env*`, `*.pem/key`,
  `*.sql`...).
- `git commit/push/reset` — только по явной просьбе пользователя.
- Не добавлять зависимости без подтверждения; сначала проверить `package.json`.
- Документацию библиотек сверять через `context7`, не по памяти.

## Разведка и контекст

- Разведку кодбазы, массовые поиски, черновые анализы — **сабагентам** (explore/plan), чтобы не
  засорять основной контекст. Основной поток держит фокус на задаче и забирает у сабагентов только
  выводы.
- Найденные грабли — сразу в `memory/known-issues.md`.
